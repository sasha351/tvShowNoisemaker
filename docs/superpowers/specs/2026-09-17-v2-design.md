# tvshow-noisemaker v2 — design spec

Date: 2026-09-17
Status: Approved

## Context

v1.1 converts a season of episodes to trimmed audio. Detection is chromaprint
pairwise matching (intro-skipper algorithm) plus a silence snap; the GUI is a
customtkinter wrapper that shells out to the CLI and scrapes log lines.

User's v2 goals, in priority order:

1. **No clipping mistakes.** Observed failures: cold opens / "previously on"
   recaps mishandled; intro end cut a little early or late.
   Bias decision: when uncertain, keep a little theme, never lose dialogue.
2. **Fastest wall time per season.**
3. **Polished UI** with a review step: confident episodes encode
   automatically, flagged ones are held for the user to preview (audio) and
   nudge before encoding.

Only one show exists as test data (Family Guy S02, 21 eps). User will supply
3–5 more shows. Git is currently broken on this machine (Xcode license not
accepted) — user must run `sudo xcodebuild -license` before any commits.
User prefers implementation via Sonnet subagents (memory).

## Root causes to fix (hypotheses, verified in Phase 0 with real data)

- **Recaps win the "longest match" contest.** `_pairwise_best_segments`
  (detector.py:791) keeps the longest matching segment per episode from any
  single pair. A recap shares 30–60 s of audio with the previous episode,
  which beats a 20–30 s theme, so the recap is cut and the theme kept.
  Fix: consensus, not longest — the intro is the segment matched across the
  most episodes at consistent length.
- **Silent median fill.** Episodes with no direct match get the median
  boundaries (detector.py:963). An episode with no intro loses 30 s of
  content. Fix: never fill silently; flag for review.
- **Silence snap can cut into dialogue.** `_snap_to_silence` picks the
  closest silence start in [−5 s, +2 s]; a pause after the first spoken word
  is a valid target. Fix: snap window asymmetric toward the safe side and
  apply an outward safety margin after snapping.
- **Chromaprint resolution is ~0.12 s per point with gaps up to 3.5 s
  allowed**, so a raw boundary can sit a couple of seconds off. Silence snap
  usually fixes it; the benchmark decides whether a finer refinement is needed.

## Architecture change

Split the monolithic `cli.run` (cli.py:291) into a library the CLI and GUI
both call in-process:

```
tvshow_noisemaker/pipeline.py
  detect(input_dir, cfg, progress) -> Plan        # probe + fingerprint + resolve + score
  encode(plan, cfg, progress, cancel) -> Summary  # existing encode phase, cancellable
  Plan / EpisodePlan dataclasses, to_json / from_json
```

`EpisodePlan`: path, duration, intro_start, intro_end, outro_start,
`confidence` (`"high" | "review" | "skip"`), `flags: list[str]` (human
reasons: "matched 1 episode only", "intro length 48 s vs season 31 s",
"no intro found", "cold open 41 s"), `source` ("config" | "fingerprint" |
"silence" | "manual").

CLI keeps its flags and adds `--detect-only PLAN.json` and
`--plan PLAN.json` (encode from a plan). Those two flags are also what the
benchmark harness and the GUI's "export ground truth" use.

GUI calls `detect`/`encode` on a worker thread with a `queue.Queue` for
progress (same pattern as today's `_reader`/`_poll`), no subprocess parsing.
Cancel = `threading.Event` checked between files + terminate the live ffmpeg
`Popen` handles (processor.py switches `subprocess.run` to `Popen` so the
handle can be registered).

## Phases

### Phase 0 — Ground truth + benchmark harness (needs user's media)

- `test_media/ground_truth.json`: `{ "<Show>/Season NN/<file>": {intro_start, intro_end, outro_start} }`, seconds, `null` for "no intro".
- `tools/bench_detection.py`: runs `pipeline.detect` on every show under
  `test_media/`, compares to ground truth, prints per-episode error in
  seconds for each boundary, max/mean, count of "would have clipped
  dialogue" (cut later than truth by > margin), flagged-vs-should-be-flagged
  confusion, and stage timings. This is the acceptance gate for Phase 2.
- Bootstrap ground truth: run detection, user confirms/corrects via the
  review UI (Phase 4) or by editing the exported plan JSON. Until Phase 4
  exists, I produce 6 s preview snippets around each cut with ffmpeg into the
  scratchpad and the user listens.

### Phase 1 — Pipeline refactor (no behaviour change)

- Create `pipeline.py` by moving the phases out of `cli.run`; `cli.run`
  becomes: parse → `detect` → log plan → `encode` → summary.
- Add `--detect-only` / `--plan`. Confidence is `"high"` for everything in
  this phase (scoring lands in Phase 2).
- Existing tests in `tests/test_cli.py` keep passing; add `tests/test_pipeline.py`
  for JSON round trip and detect→encode split.

### Phase 2 — Detection fixes (gate: bench_detection)

In `detector.py`:

1. **Consensus intro/outro.** Replace longest-per-episode in
   `_pairwise_best_segments` with: collect every pair match, cluster by
   length (±3 s); winning cluster = most episodes covered, tie → longer.
   Per episode use its match from the winning cluster; matches outside it
   (recaps, two-parters) are recorded as flags, not used.
2. **No silent median fill.** Episodes without a direct match → boundaries
   `None`, `confidence="review"`, flag "no intro match (season median 31 s)";
   the season median is offered as the prefilled suggestion in the UI.
3. **Safe snap + margin.** `_snap_to_silence` for `intro_end` searches
   [−5 s, +2 s] as now but only accepts a later silence if it is the first
   silence after the boundary (nothing spoken in between); then apply
   `cut_margin` (Config, default 0.5 s): `intro_start += m`, `intro_end -= m`,
   `outro_start += m`. Ordering guard stays.
4. **Confidence scoring** in `pipeline.detect`: `high` requires intro
   matched in ≥2 pairs inside the consensus cluster (or config timestamps),
   length within ±3 s of cluster median, outro likewise or absent-by-consensus.
   Everything else `review`. Files with no boundaries at all and no
   fallbacks → `skip`.
5. **Only if the benchmark still shows > 1 s boundary error**: fine
   refinement by cross-correlating 16 kHz PCM envelopes ±3 s around the
   boundary against the consensus reference episode (reuse
   `_extract_audio_pcm` and the FFT code already in detector.py).
6. Chapter markers: Family Guy mkvs have generic chapters (266 s), not
   intro markers. Skipped unless a user-supplied show has real ones; noted
   as a `ponytail:` comment.

Tests: unit tests for the clustering (synthetic pair matches including a
recap that is longer than the theme), the snap acceptance rule, the margin,
and the scoring table.

### Phase 3 — Performance (gate: benchmark matrix, warm and cold)

Measured baseline (improvements.txt, 21 files, M1 Pro 8-core): warm 1m10s
with 8 workers, encode-bound; cold adds ~1m14s in boundaries.

1. Add `tools/bench_perf.sh` that runs cold/warm with `--benchmark-fingerprint`
   and `/usr/bin/time -l`, so every change below is measured, not assumed.
2. Cache silence-snap windows (same key scheme as `_silence_cache_path`).
   Cold "boundaries" stage today is dominated by uncached ffmpeg calls.
3. Fewer silence-detection fallbacks: with consensus + review flow, the
   full-window `detect_by_silence` only runs for `review` episodes.
4. `m4a` uses `aac_at` (AudioToolbox hardware encoder, present in this
   ffmpeg) instead of the software `aac` encoder. mp3 stays libmp3lame
   (single-threaded, already parallel across files; no faster mp3 exists).
5. GUI multi-folder pipelining: detect folder N+1 while folder N encodes
   (two worker threads, encode pool sized to CPU count minus detect workers).
6. Report the before/after table in the plan doc; expected wins are on cold
   runs and m4a; mp3 warm runs are already near CPU-bound.

### Phase 4 — GUI v2 (customtkinter, in-process)

Keep customtkinter (installed, themed, works). Layout:

- Top: show list + destination + format/quality (as now, tidied: aligned
  grid, consistent paddings, section captions).
- Status card: phase-aware ("Detecting 12/21…", "Encoding 8/18…"),
  determinate bar per phase, ETA from the encode rate.
- **Review panel** (appears when a folder's plan has `review` episodes; the
  confident ones start encoding immediately): one row per flagged episode —
  name, flag text, three editable time fields (mm:ss.s), a `▶` per field that
  plays a 6 s snippet spanning the cut (ffmpeg → wav in scratch → `afplay`,
  on a thread, stop button), a "Skip" checkbox, and "Approve" per row plus
  "Approve all". Approved rows join the encode queue.
- "Review every episode" checkbox (off by default) forces all rows into the
  panel. "Export approved cuts…" writes the plan JSON (feeds ground truth).
- Activity feed and details log stay; log becomes a `logging.Handler` that
  posts to the queue, no more stdout scraping (`parse_total`,
  `is_file_result`, `friendly_result_line` and their tests go away).
- Cancel terminates live ffmpeg processes and stops both threads.

Tests: parser/format helpers that survive, review-row model
(approve/skip/edit → EpisodePlan), snippet command builder. GUI smoke test
runs `App` headless where tkinter allows.
